# Contract changes (Service interface, contract version 1)

Changes to the interface Plan 2b consumes, after the 2a plan's "Service interface". Each one names its ruling.

| Date | Change | Compatibility | Ruling |
|---|---|---|---|
| 2026-11-04 | `Result.latency` gains `resumes: int` (default 0): the number of answers the candidate resumed right after a turn end, which were merged back into one turn. | Added and optional. `CONTRACT_VERSION` stays 1, and 2b's models ignore unknown fields (`extra="ignore"`). The schema and the example result are regenerated. | AT2 (turn-fix plan, Task 2) |
| 2026-11-04 | New settings `TURN_GRACE_S` (default 1.5, 0–5) and `RESUME_WINDOW_S` (default 2.0, 0–5). | Optional environment variables; JobLens's compose doesn't need to set them. | AT1, AT2 |
| 2026-11-04 | `GET /health`: `live_session` (an id) is replaced by `busy: bool`. `409 busy` on `POST /sessions` no longer carries `session_id` (only `code` and `message`). | Breaking only for a reader of those fields. JobLens never reads `live_session`. Its client reads `detail.get("session_id")`, which now yields `None`, so `InterviewerBusy(None)` still raises `Conflict(ONE_LIVE)`. **JobLens must change:** the `test_interviewer_client` busy test and `FakeInterviewer`'s `InterviewerBusy("svc-0")` stop expecting an id (use `None`), and `InterviewerBusy`'s message drops "with session …". `CONTRACT_VERSION` stays 1. | AF1 |
| 2026-11-04 | Audio-check plan contract, `mic_level.rms` (clarification before first release): rounded to 4 decimals but **floored at 0.0001 when any sample in the 200 ms window is non-zero**, so `0.0` means digital silence only. A quiet room (±1–2 LSB, RMS ≈ 0.00004) would otherwise round to `0.0` and be indistinguishable from a dead mic, and the browser's "warning clears on `rms > 0`" rule would never fire for it. | Narrows an unreleased message; no consumer exists yet. JobLens: treat `rms > 0` as "audio is arriving" (unchanged), and scale the level bar with that floor in mind (e.g. a log scale). `CONTRACT_VERSION` stays 1. | C1 (audio-check builder, Task 1; spec §3.3 + UX3) |
| 2026-11-04 | New audio-check endpoints: `POST /checks`, `POST`/`PATCH /checks/{id}/offer`, `GET /checks/{id}` (`CheckStatus`), `POST /checks/{id}/end` (202 only once the lock is free; waits ≤ 5 s, then cancels). Checks share the one-session lock and token rules with sessions; `GET /health` `busy` is also true while a check is waiting/live; checks are SmallWebRTC only (409 `wrong_state` otherwise); new error 404 `unknown_check`. | Added; `CONTRACT_VERSION` stays 1. | UX7, UXP1, UXP2 |
| 2026-11-04 | RTVI server messages `mic_level` (`rms`, ~5/s) and `silent_input` (`reason`: `zeros` / `no_audio`) on sessions **and** checks. | Added; `CONTRACT_VERSION` stays 1. A client that ignores server messages is unaffected. | §3.3 + UX3, UXP2 |
| 2026-11-04 | Check-only RTVI messages: server `heard` and `check_ended`; client messages `listen` and `play_prompt` (ignored during interviews). | Added; `CONTRACT_VERSION` stays 1. | UX7, UXP1 |
| 2026-11-04 | New setting `BARGE_IN_MIN_S` (default 0 = today, range 0–3; 0.8 is the no-headset fallback). | Optional environment variable; JobLens's compose doesn't set it (UXP3). `CONTRACT_VERSION` stays 1. | UX5, UXP3 |
| 2026-11-04 | Audio-check plan contract, **digital silence** (clarification before first release): a frame counts as digital silence when every sample is 0 **or** no sample exceeds ±1 and at most 5 % of samples are non-zero. The check e2e showed Chromium's all-zero fake mic reaching the pipeline (after Opus and resampling) as 20 ms frames with exactly 2 of 320 samples at ±1, so "all exactly 0" never fired. `silent_input` `zeros` uses this definition, and `mic_level.rms` is exactly `0.0` for a window made only of such frames (the C1 floor of 0.0001 applies to every other window). Room noise, even at ±1 LSB, has far more non-zero samples and still never counts (UX3). | Narrows an unreleased message; no consumer exists yet. JobLens unchanged: `silent_input` still means "the interviewer receives silence", and `rms > 0` still means "audio is arriving". `CONTRACT_VERSION` stays 1. | C2 (audio-check builder, Task 6; spec §3.1 step 2, acceptance 1, UX3) |
